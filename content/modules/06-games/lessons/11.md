## Lesson objectives
By the end, the student can…
- Pick a good use of AI in a game (and avoid risky ones).
- Add a Claude-powered feature with the key on the server, limits and a fallback.
- Write character rules (a **system prompt**) that keep the AI on-topic, kind and in character.

## Words for today
- **NPC** — a non-player character: someone in the game the computer controls.
- **System prompt** (again) — the rules and personality you give Claude every time.
- **Fallback** — what the game does if the AI is slow or off (a ready-made line).
- **Latency** — waiting time. Games feel bad if they freeze while waiting.
- **In character** — the AI talks like your game's character and stays in your game's world.


## 2. Mini-lesson — Smart, safe AI in games (15 min · 1-on-1: 10 min)
Show **Visual 1**.

**Great uses:** a character who reacts to how you played ("Wow, 3 levels without a hit!"), hints when you're stuck, new riddles or level names between rounds, a funny "game over" line.

**Risky uses:** letting AI change the rules or the score during play, open chat with strangers' messages, anything that freezes the game while waiting.

**The safe pattern** (same as your app in Module 5):
1. Key only in **Vercel environment variables**.
2. A **server function** calls Claude, with a **daily limit** and short answers.
3. Call the AI **between** rounds or levels, not in the middle of fast action.
4. Always have a **fallback** line if it's slow, off or over the limit.
5. A **system prompt** with personality and rules: stay in character, keep it kind and short, no personal questions, nothing scary or rude.

**Picking a model:** Claude Opus 5.5 (`claude-opus-5-5`) gives the best lines; Claude Haiku 5.5 (`claude-haiku-5-5`) is faster and much cheaper, which is great for quick game lines. Try both!

## 3. Hands-on build — Claude in your game (40 min · 1-on-1: 28 min)
1. Write your character's system prompt: name, personality, how they talk, rules.
2. Add `ANTHROPIC_API_KEY` in Vercel → Settings → Environment Variables.
3. Ask Claude Code:
```
Add an AI feature to my game: [describe it, like "between levels, the gardener gives one short tip based on how the player did"].
Use a Vercel server function that calls the Claude API (Messages API) with model claude-opus-5-5, reading ANTHROPIC_API_KEY from environment variables. Never put the key in the game code.
Send only the game stats needed (level, score, what made them lose). Keep answers under 25 words.
Limit to [30] AI calls per player per day. If the AI is slow (over 3 seconds), off or over the limit, show one of these fallback lines: [list].
Use this system prompt: [paste]. Explain each part simply.
```
4. Deploy and test with your 5 test inputs. Check the answers, the speed and the cost.

**Checkpoint 1 (+20 XP):** AI feature works between rounds, key only in Vercel settings.
**Checkpoint 2 (+20 XP):** limits and fallback lines work, and you wrote down the cost of 10 calls.

## 4. Game / challenge — Break Character (10 min · 1-on-1: 7 min)
Try to make the AI character break its rules: make it say something rude, talk about something off-topic, or give away the ending. Does it stay in character?

```group
Every AI that stays in character against 4 tries: +15 XP. Everyone: +5.
```

```solo
**Student vs. Bolt.** 4 tries each to break the other's AI character. Each try blocked = 1 point for the builder. +15 XP for playing, +5 for the win.
```

## 5. Share-out — Meet my character (10 min · 1-on-1: 5 min)
Show the AI feature in action and say what 10 calls cost.

```solo
The student demos it and explains the fallback lines: "If the AI is off, my game still works because ___."
```

## 6. Exit ticket (5 min)
1. Why call the AI between rounds, not during fast action?
2. What's a fallback, and why does every AI feature need one?
3. Name 2 rules in your character's system prompt.

```solo
Ask out loud. Check the Console usage together.
```

## Differentiation
- **Extra help:** one AI "game over" line per round, nothing else. Use the exact prompt.
- **Extra challenge:** have Claude generate new riddles or level names between rounds, checked by your code (length, no rude words) before showing them.
- **1-on-1 tip:** the character's voice is where students shine. Spend time on the personality; it's what players remember.
