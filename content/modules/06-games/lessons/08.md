## Lesson objectives
By the end, the student can…
- Explain the **flow zone**: not too easy, not too hard.
- Plan a **difficulty curve** with teach → practice → test.
- Build 3 or more levels or waves that teach the game without long instructions.

## Words for today
- **Level** — one stage of a game, with its own layout or challenge.
- **Wave** — a round of enemies or items that gets harder each time.
- **Difficulty curve** — how the game gets harder over time.
- **Flow zone** — when the challenge matches your skill, so it's fun, not boring or stressful.
- **Teach by doing** — the first level shows how to play by letting you try it safely.

## 1. Warm-up — The first 30 seconds (10 min · 1-on-1: 5 min)
```teacher
Good games teach you by letting you play, not by long text. Today you build levels that start easy and get harder. Let's play two games.
```

Play the first 30 seconds of 2 games. How did each game teach you what to do? Was there a lot of text, or did you learn by trying?

```solo
Play a game the student knows well. Ask them to remember how they learned it. Did they read anything?
```

## 2. Mini-lesson — The flow zone (15 min · 1-on-1: 10 min)
Show **Visual 1**: skill goes up as you play, so difficulty should go up too. Too far above = stress. Too far below = boredom. In between = **flow**.

**Teach → practice → test** (**Visual 2**):
1. **Teach:** one new idea in a safe place (the first jump has no danger under it).
2. **Practice:** use the idea a few times, a little harder.
3. **Test:** combine it with something you learned before.
Then teach the next idea.

**Ways to make it harder:** faster, more things at once, less time, smaller targets, new enemy types. Change ONE thing at a time. Give a short break (an easy moment) after a hard part.

## 3. Hands-on build — Build your levels (35 min · 1-on-1: 25 min)
1. List your mechanics. Plan 3 to 5 levels or waves on paper with teach → practice → test.
2. Draw the difficulty curve: what gets harder in each level?
3. Ask Claude Code:
```
Add [3] levels (or waves) to my game. Level 1 teaches [mechanic] safely with a short hint on screen. Level 2 practices it, a little harder. Level 3 tests it together with [other mechanic].
Here's what changes each level: [speed, number of enemies, time]. Put all level settings in one easy-to-edit list.
Show "Level 2!" between levels and keep the score.
```
4. Play all levels. Tune any level that feels too hard or too easy.

**Checkpoint 1 (+20 XP):** level plan with teach → practice → test and a difficulty curve.
**Checkpoint 2 (+20 XP):** 3 or more levels built and tuned.

```group
Pairs play each other's level 1 without any help: did it teach them?
```

```solo
You play level 1 as if you've never seen the game, saying what you think you're supposed to do. If you're wrong, level 1 needs a better hint.
```

> 🛡️ **Kind design moment:** add an easier mode or a "skip level" option so more people can enjoy your game, and never shame players for losing.

## 4. Game / challenge — Where Did You Quit? (15 min · 1-on-1: 10 min)
Players try all your levels. Note the level and second where each player fails or wants to quit. That's where the curve is too steep.

```group
Game where most players reach the last level: +15 XP. Everyone: +5.
```

```solo
**Student vs. Bolt.** You play their levels; they play yours. Mark where each of you struggled. Tune one spot and try again. +15 XP for playing, +5 if you make it further the second time.
```

## 5. Share-out — Design story (10 min · 1-on-1: 5 min)
Pick one level and explain: "This level teaches ___ by ___."

```solo
The student explains their best level like a game designer interview.
```

## 6. Exit ticket (5 min)
1. What is the flow zone?
2. What do teach, practice and test mean in level design?
3. Where did players struggle in your game?

```solo
Ask out loud. Next lesson, we tune the numbers that make it all fair.
```

Above it a red area "TOO HARD: stress", below it a blue area "TOO EASY: boring". A tiny original game character walking along the green band. Flat design, readable.

**Visual 2 — Teach, practice, test.**
```prompt
A three-panel level sketch, 16:9, titled "TEACH → PRACTICE → TEST". Panel 1: a small gap to jump with soft grass below (safe). Panel 2: three gaps in a row. Panel 3: a gap with a moving bug to avoid. A small original character in each panel. Bright pixel-art style, readable labels.
```

## Differentiation
- **Extra help:** 3 waves where just one number changes (speed). Use the prompt as-is.
- **Extra challenge:** add a boss level that combines everything, or a level editor where players can make their own level.
- **1-on-1 tip:** watch where the student themself gets frustrated in other games. Their own feelings are great design data.
