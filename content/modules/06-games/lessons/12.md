## Lesson objectives
By the end, the student can…
- Run a playtest with new players and sort bugs by how bad they are.
- Make their game more **accessible**: control options, color-safe design, pause, difficulty and effect settings.
- Check their game is **fair and kind**, and ship a polished version with patch notes.

## Words for today
- **Playtester** — someone who plays your game to help you improve it.
- **Bug triage** — sorting bugs by how bad they are, so you fix the worst first.
- **Accessible** (again) — easy to play for more people, including people with disabilities.
- **Color-safe** — the game still works for people who see colors in a different way (use shapes and icons too, not only color).
- **Patch notes** — a short list of what changed in an update.

## 1. Warm-up — Fair or sneaky? (10 min · 1-on-1: 5 min)
```teacher
Almost ready to ship! Today you test, polish and check that your game plays fair. Some games trick players. Let's spot the tricks.
```

Look at examples of game designs: a "come back in 4 hours or pay now" timer, a daily reward that disappears if you miss a day, a loot box, a clear one-time price. Which feel fair? Which feel sneaky? Why?

```solo
Ask the student about a game that made them feel pressured to keep playing or pay. How did it do it?
```

## 2. Mini-lesson — Two checklists (12 min · 1-on-1: 8 min)
**Bug triage** (**Visual 1**): 🔴 **Game-breaking** (crashes, can't finish) → fix now. 🟠 **Annoying** (confusing, unfair moments) → fix next. 🟢 **Tiny** (a pixel off) → if there's time.

**Fair & Fun Checklist** (**Visual 2**):
- ♿ **Access:** keyboard AND touch; a pause button; easy/normal modes; effects and flashes can be turned off; color plus shapes or icons; text big enough to read.
- 🤝 **Fair:** no losing from pure luck; rules are clear; the leaderboard is moderated.
- 💛 **Kind:** no tricks to make people play longer than they want (no guilt timers, no streak punishments); no pay-to-win; no "loot box" gambling; credits for everything you used.

## 3. Hands-on build — Playtest and polish (43 min · 1-on-1: 30 min)
1. Run a playtest with 3 or more new players: watch silently, take notes, then a 4-question survey (fun? confusing? fair? would you play again?).
2. Make a bug list and sort it into 🔴 🟠 🟢.
3. Ask Claude Code to fix every 🔴 and as many 🟠 as you can, one at a time, playing after each.
4. Go through the Fair & Fun Checklist. Add the missing options (pause, difficulty, effects off, color-safe icons).
5. Write patch notes and deploy.

**Checkpoint 1 (+20 XP):** playtest done with 3+ players; bug list sorted.
**Checkpoint 2 (+20 XP):** all 🔴 fixed, Fair & Fun Checklist passed, patch notes written.

```group
Testers rotate around the room; makers watch silently.
```

```solo
Be the first playtester and narrate everything. Then set up a video call with one more new player while the student watches silently.
```

> 🛡️ **Kind design moment:** a great game is one people are happy they played, not one they can't stop playing. Design for good feelings, not for pressure.

## 4. Game / challenge — Play It a New Way (10 min · 1-on-1: 7 min)
Play your game with one limit: one hand only, sound off, no color (grayscale mode on the phone), or touch only. Can you still play? Fix one thing that got in the way.

```group
Each game that works with all 4 limits: +15 XP. Everyone who fixes a problem: +5.
```

```solo
**Student vs. Bolt.** Each of you picks 2 limits and plays the other's game with them. Fix one problem each. +15 XP for playing, +5 for a fix.
```

## 5. Share-out — Patch notes (10 min · 1-on-1: 5 min)
Read your patch notes like big news from a game studio.

```solo
Post the patch notes on the game's start screen or a "What's new" page.
```

## 6. Exit ticket (5 min)
1. What's bug triage, and why fix 🔴 first?
2. Name 3 things that make a game more accessible.
3. Name one sneaky design trick you'll never use.

```solo
Ask out loud. Next lesson is the Boss: Game Launch Arcade!
```

## Differentiation
- **Extra help:** fix the 🔴 bugs and add a pause button and an easy mode.
- **Extra challenge:** let players choose their own keys and a subtitle option for any spoken lines.
- **1-on-1 tip:** the student's own feelings about sneaky games make the ethics part real. Let them lead that talk.
