## Lesson objectives
By the end, the student can…
- Ask Claude Code to build version 1 of their game from a game plan.
- Build it in small steps: core loop first, then screens, then extras.
- Put it online with Vercel and play it on a phone and a computer.

## Words for today
- **Game state** — what's going on right now: start screen, playing, paused, game over.
- **Canvas** — the part of a web page where a game is drawn.
- **Game library** — ready-made code that helps with games (like Phaser). Claude Code can use one or plain code.
- **Build in steps** — add one thing, play it, then add the next.

## 1. Warm-up — Plan check (10 min · 1-on-1: 5 min)
```teacher
Today you build version 1 of your game with Claude Code. Gray boxes are fine. Make it fun first, pretty later. Read me your plan.
```

Read your elevator pitch, core loop and scope out loud. Anything to cut before building?

```solo
Ask: "If we only had time for ONE feature, what would it be?" That's step 1 of the build.
```

## 2. Mini-lesson — Build in steps (10 min · 1-on-1: 7 min)
Show **Visual 1**: **Step 1 core loop → Step 2 win and lose → Step 3 start, pause and game over screens → Step 4 score → (later) art, sound, levels.** Play after every step!

**The build prompt** (step 1):
```
Build version 1 of my original browser game. Here is my one-page game plan: [paste].
Start with ONLY the core loop, using simple shapes (no art yet). Controls: keyboard AND touch.
Use plain HTML, CSS and JavaScript with a canvas (or a free game library like Phaser if it makes this much easier: tell me which and why).
Put all the tuning numbers in one settings section at the top.
Explain what you built in simple words, and how to test it.
```
Then ask for each next step, one at a time.

**Online:** same as your app: GitHub repo → Claude Code builds → Vercel imports the repo → a link you can share.

## 3. Hands-on build — Version 1 (45 min · 1-on-1: 31 min)
1. Make a GitHub repo for the game and open it in Claude Code.
2. Step 1: core loop. Play it.
3. Step 2: win and lose. Play it.
4. Step 3: start, pause and game over screens (with "Play again"). Play it.
5. Step 4: score. Play it.
6. Import the repo in Vercel, deploy, and play on a phone.

**Checkpoint 1 (+20 XP):** core loop + win and lose work.
**Checkpoint 2 (+20 XP):** screens and score work, and the game is live on Vercel.

```group
Walk around and ask: "Which step are you on? Did you play it after the last change?"
```

```solo
Hold the plan and tick off steps. After each step, play it yourself for 30 seconds and say one thing that feels good and one that feels off.
```

> 🛡️ **Repo moment:** nothing private in the repo. If you use any sound or picture you didn't make, check it's free to use and note where it came from.

## 4. Game / challenge — First Players (10 min · 1-on-1: 7 min)
Two people play your game for 2 minutes each. You watch silently. Write down: where did they get stuck? Did they want to play again?

```group
Swap with another house. Every "play again!" = +3 points. Most points: +15 XP. Everyone: +5.
```

```solo
**Student vs. Bolt.** You play their game; they play your demo. Count "play again" moments. +15 XP for playing, +5 if you asked to play again.
```

## 5. Share-out — It's live! (10 min · 1-on-1: 5 min)
Share your game link. Play it on a phone together.

```solo
Celebrate! Send the link to one friend tonight and ask for their high score.
```

## 6. Exit ticket (5 min)
1. Why build a game in steps?
2. What are the 4 game states in your game?
3. What did first players get stuck on?

```solo
Ask out loud. Add the stuck spots to the fix list.
```

## Differentiation
- **Extra help:** start from the gray-box prototype artifact and ask Claude Code to turn it into a repo. Steps 1 and 2 only today.
- **Extra challenge:** add a settings screen (sound on/off, difficulty) that's remembered after refresh.
- **1-on-1 tip:** resist adding art today. A fun gray-box game is the best foundation.
