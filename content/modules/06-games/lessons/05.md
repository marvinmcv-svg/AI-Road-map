## Lesson objectives
By the end, the student can…
- Write a **one-page game plan** for an original game.
- Describe the **core loop** and the **win and lose** rules clearly.
- Test the core loop with a paper or quick Claude prototype before building the full game.

## Words for today
- **Game plan (design doc)** — one page that says what your game is and how it works.
- **Elevator pitch** — your game in one sentence: "It's a ___ where you ___ to ___."
- **Win state / lose state** — what makes you win, and what makes you lose.
- **Controls** — how the player moves and acts (keys, taps, swipes).
- **Scope** — how big the project is. Keep it small enough to finish!

## 1. Warm-up — Idea Sparks (10 min · 1-on-1: 5 min)
```teacher
Now you design your OWN game. You will plan it on one page first. Start small. Let's draw some idea cards.
```

Draw 2 Idea Spark cards (a verb and a theme). In 3 minutes, sketch a game that uses both. Do it twice.

```solo
You both draw cards and sketch at the same time. Show each other. Steal the best bits!
```

## 2. Mini-lesson — The One-Page Game Plan (12 min · 1-on-1: 8 min)
Show **Visual 1**:
| Part | Example |
|---|---|
| 💡 **Elevator pitch** | "It's a garden game where you grow flowers fast before the bugs eat them." |
| 🙋 **Player** | Busy students who want a 2-minute fun break |
| 🔁 **Core loop** | Tap a seed → water it → shoo bugs → harvest → repeat |
| ⚙️ **Mechanics** | Tap to plant, swipe to shoo, hold to water |
| 🏆 **Win / lose** | Win: 20 flowers in 2 minutes. Lose: bugs eat 5 plants |
| 🎮 **Controls** | Touch first; mouse works too |
| 🎨 **Look & sound** | Soft pastel, cute, gentle plucky music |
| ✂️ **Scope** | 1 level type, 3 difficulty steps, no story mode |

**The scope rule:** a small game that's finished and fun beats a huge game that's half done.

## 3. Hands-on build — Plan and prove the loop (38 min · 1-on-1: 27 min)
1. Fill in your One-Page Game Plan.
2. Ask Claude to poke holes in it: "Here's my game plan: [paste]. What's unclear? What could be boring after 2 minutes? What's too big for 6 lessons? Suggest how to make the scope smaller."
3. Prove the core loop: make a quick paper version OR ask Claude for a tiny artifact with just the core loop (gray boxes, no art).
4. Play it. Is the loop fun for 30 seconds? Change one thing and try again.

**Checkpoint 1 (+20 XP):** One-Page Game Plan complete, scope checked with Claude.
**Checkpoint 2 (+20 XP):** core loop tested (paper or gray-box prototype), with one change made.

```group
Pairs swap plans and write one question about each part.
```

```solo
Play the gray-box prototype together. If the loop isn't fun with gray boxes, art won't save it. Help the student find the fun first.
```

> 🛡️ **Original idea moment:** your game should be your own idea. It's fine to be inspired by game types you love, but use your own name, characters and world.

## 4. Game / challenge — Pitch and Poke (15 min · 1-on-1: 10 min)
Pitch your game in 30 seconds. Listeners ask "poke" questions: "What happens if…?" "Why would I play again?" Write down every question you can't answer yet.

```group
Best pitch (class vote): +15 XP. Everyone who pitches: +5.
```

```solo
**Student vs. Bolt.** You each pitch a game and poke the other's with 3 questions. Whoever answers more questions clearly wins. +15 XP for playing, +5 for the win.
```

## 5. Share-out — One sentence (10 min · 1-on-1: 5 min)
Say your elevator pitch. Can listeners explain your game back to you?

```solo
Ask a guest (or a family member later) to hear the pitch and explain the game back. If they can't, sharpen the sentence.
```

## 6. Exit ticket (5 min)
1. What's your elevator pitch?
2. What's your core loop?
3. What did you cut to keep the scope small?

```solo
Ask out loud. The plan is the brief for Claude Code next lesson.
```

## Differentiation
- **Extra help:** start from an Idea Spark and a filled-in example plan. Change the theme and one mechanic.
- **Extra challenge:** add a "secret" mechanic players discover after a few tries, and plan how the game hints at it.
- **1-on-1 tip:** guard the scope. Ask "Can we finish this in 6 lessons?" every time a new feature appears. Put the rest on a Later list.
