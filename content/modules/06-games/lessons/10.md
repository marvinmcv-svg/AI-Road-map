## Lesson objectives
By the end, the student can…
- Save a **high score** on the device.
- Add an online **leaderboard** with Supabase, using nicknames and Row Level Security.
- Explain why leaderboards attract cheating, and add simple **fair-play** checks.

## Words for today
- **High score** — the best score so far.
- **Leaderboard** — a ranked list of the best scores from many players.
- **Nickname** — a made-up player name, not a real name.
- **Validation** — checking that data makes sense before saving it (a score can't be bigger than possible).
- **Cheating** — breaking the rules to get a higher score. In a browser game, a clever player can always try.

## 1. Warm-up — Beat my score (10 min · 1-on-1: 5 min)
Play the demo game. The teacher's high score is on the screen. Can you beat it? How did seeing a score change how you played?

```solo
Play for the high score, back and forth. Ask: "Would you come back tomorrow to beat it?"
```

## 2. Mini-lesson — From high score to leaderboard (15 min · 1-on-1: 10 min)
Show **Visual 1**:
1. **Local high score:** saved on this device. Simple and private.
2. **Online leaderboard:** a Supabase table with `nickname`, `score`, `created_at`. Anyone can **read** the top 10; players can only **add** a score, never change or delete other people's (Row Level Security!).

**The Fair Leaderboard checklist** (**Visual 2**):
- 🙋 **Nicknames only:** never real names, emails or ages on a public list.
- 🧹 **Name filter:** block rude words; limit nicknames to 12 letters.
- 🔢 **Score limits:** a score can't be higher than the game allows in the time played.
- 🐢 **Slow down spam:** one score per finished game; ignore super fast repeats.
- 🗑️ **Clean-up:** you can remove bad entries.

**Honest truth:** in a browser game, a determined player can still try to cheat. Checks make it harder and less tempting. Real games check scores on a server; that's a great level-up.

## 3. Hands-on build — Scores (40 min · 1-on-1: 28 min)
1. Ask Claude Code for a local high score shown on the start and game over screens. Test it.
2. Make a `scores` table in Supabase and turn on Row Level Security.
3. Ask Claude Code:
```
Add an online top-10 leaderboard with Supabase (URL and public key from environment variables).
Table "scores": nickname (max 12 letters), score, created_at.
After game over, let the player enter a nickname and submit once. Block rude words, empty names and scores higher than [max possible for the time played].
Tell me the Row Level Security rules so anyone can read the top 10 and insert a score, but nobody can update or delete. Explain each part simply.
```
4. Add the RLS rules (read them!). Add the settings in Vercel and deploy.
5. Submit real scores from 2 devices.

**Checkpoint 1 (+20 XP):** local high score works.
**Checkpoint 2 (+20 XP):** online leaderboard works with RLS, nickname filter and score limit.

```group
Pairs post scores to each other's leaderboards.
```

```solo
Play a few rounds each and fill the leaderboard together. Then do the cheat test below.
```

> 🛡️ **Privacy moment:** a public leaderboard is public. Nicknames only, nothing that tells people who or where you are.

## 4. Game / challenge — Try to Cheat (Your Own Game!) (10 min · 1-on-1: 7 min)
Try to break your own leaderboard: a rude name, a super long name, a score of 999,999, submitting 10 times fast. Which ones get through? Fix one.

```group
Every leaderboard that blocks 3 of 4 tricks: +15 XP. Everyone: +5.
```

```solo
**Student vs. Bolt.** With permission, you try the 4 tricks on their leaderboard; they try them on your demo. Each trick blocked = 1 point for the builder. +15 XP for playing, +5 for the win.
```

## 5. Share-out — Hall of fame (10 min · 1-on-1: 5 min)
Show your leaderboard with real scores. Who's on top?

```solo
Send the game link to 2 friends and challenge them to get on the board.
```

## 6. Exit ticket (5 min)
1. What's the difference between a local high score and a leaderboard?
2. Name 3 fair leaderboard rules.
3. Why can't a browser game stop all cheating?

```solo
Ask out loud. Only test cheating on your own games, or with permission.
```

## Differentiation
- **Extra help:** local high score only, plus a "share my score" button that copies a message. No online board.
- **Extra challenge:** check scores on the server with a Vercel function before saving (the player sends the game's event log, the server re-checks the score).
- **1-on-1 tip:** reuse the Supabase project skills from Module 5. Point out how much faster it goes the second time.
