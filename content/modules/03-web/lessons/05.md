## Lesson objectives
By the end, the student can…
- Describe an interactive section clearly enough for Claude to build it.
- Test it and write a good **bug report**: what I did, what I expected, what happened.
- Have Claude Code add the finished section to their live site.

## Words for today
- **Vibe coding** — building software by describing what you want to an AI, then testing and fixing it.
- **Interactive** — it does something when you click or type.
- **Artifact** — Claude's live preview of what it built, right next to the chat.
- **Bug** — a mistake in the code that makes it act wrong.
- **Bug report** — a clear note about a bug: what you did, what should happen, what really happened.

## 1. Warm-up — Play the quiz (10 min · 1-on-1: 5 min)
```teacher
Vibe coding means you say what you want, and Claude writes the code. Today you add something special to your site, like a quiz. Try mine first.
```

Play your demo "Which bottle is for you?" quiz. Then ask: "What would a quiz or tool on YOUR site help buyers do?"

```solo
The student plays the quiz, then tries to break it (click fast, skip questions). Did anything go wrong? That's a bug!
```

## 2. Mini-lesson — The vibe coding loop (12 min · 1-on-1: 8 min)
Show **Visual 1**. The loop:
1. **Ask:** use the Web Prompt Recipe. Be exact about what happens on each click.
2. **Test:** click everything in the artifact, try weird things, make the window narrow like a phone.
3. **Describe the bug:** "When I click 'Next' on question 3, nothing happens. It should show my result."
4. **Fix:** Claude changes the code. Test again.

**Ideas for your section:**
- 🧭 "Which product is for you?" quiz (3 questions → a result + button)
- 🎨 Color chooser (click a color, the product picture changes)
- 🧮 Price calculator (how many → total price)
- ⏳ Countdown to launch day (only if the date is real!)

**Why an artifact first?** It's the fastest place to try ideas: you see it right away and nothing on your real site can break.

**Then add it to the site:** in Claude Code, say: "Add this section to my site under 'Reasons'. Here is the code: [paste the artifact code]. Make it match our colors and fonts. Keep everything else the same." Check it, then let Vercel deploy it.

## 3. Hands-on build — Code your section (43 min · 1-on-1: 30 min)
1. Pick one idea. Write what happens on every click (a mini plan).
2. Ask Claude to build it as an artifact, with the recipe + your plan.
3. Test it. Write at least 2 bug reports and get them fixed.
4. Make it match your brand (colors, fonts, button style).
5. Ask Claude Code to add it to your site. Check the live site after Vercel deploys.

**Checkpoint 1 (+20 XP):** section works as an artifact + 2 bug reports in the Prompt Log.
**Checkpoint 2 (+20 XP):** section live on the real site and working on a phone.

```group
Pairs test each other's sections and write bug reports for each other.
```

```solo
You are the tester. Try to break it on purpose. Every time you find something, the student writes the bug report and gives it to Claude. Don't fix it for them.
```

> 🛡️ **Code safety moment:** only add code you got from Claude or sources you trust. Never add code that asks visitors for passwords or private info. Ask Claude "Is there anything in this code that collects data or sends it anywhere?" if you're not sure.

## 4. Game / challenge — Bug Bounty (10 min · 1-on-1: 7 min)
Swap sections. Find bugs in 5 minutes. A good bug report (did, expected, happened) earns 1 point.

```group
Most good bug reports: +15 XP. Everyone: +5.
```

```solo
**Student vs. Bolt.** You both ask Claude for a tiny "click counter" artifact in 3 minutes, then swap and hunt bugs. Best bug report wins. +15 XP for playing, +5 for the win.
```

## 5. Share-out — How it works (10 min · 1-on-1: 5 min)
Show your section on the live site. Explain how it helps buyers decide.

```solo
The student shows it to a guest if possible. Watch the guest use it without help. Where did they hesitate?
```

## 6. Exit ticket (5 min)
1. What are the 3 parts of a good bug report?
2. Why try a new section as an artifact first?
3. What does your section help buyers do?

```solo
Ask out loud. Check that the change is saved in the GitHub repo.
```

## Differentiation
- **Extra help:** start from the quiz idea with a ready-made prompt. 2 questions is enough. The artifact link on its own is fine for today.
- **Extra challenge:** make the quiz result button link straight to the matching product on your shop page (lesson 7). Or remember the visitor's choice after a refresh.
- **1-on-1 tip:** the student's own bug reports are the real lesson. Praise a clear bug report more than a working feature.
