## Lesson objectives
By the end, the student can…
- Ask Claude Code to build their whole landing page from their wireframe and copy.
- Add their brand colors, fonts, logo, pictures and launch video.
- Put the site online with Vercel, so it has a real web address.

## Words for today
- **Claude Code** — Claude working as a coder: it makes and changes all the files of a project for you.
- **Repo (repository)** — a folder for a project's files, kept on GitHub. It remembers every change.
- **Commit** — a saved change in the repo, with a short note about what changed.
- **Deploy** — putting your site online. Vercel does it again every time the repo changes.
- **Embed** — putting something from another place (like a YouTube video) inside your page.

## 1. Warm-up — Plan check (10 min · 1-on-1: 5 min)
Recall: name the 6 landing page parts. Then read your hero copy out loud. Is it still clear? Any last fix?

```solo
The student reads the hero; you say what you think it sells. If you're wrong, fix the copy before building.
```

## 2. Mini-lesson — From words to a live website (10 min · 1-on-1: 7 min)
Show **Visual 1**. The path:
1. **GitHub:** make a new, empty repo (like `sipsquad-site`).
2. **Claude Code:** open it, pick that repo, and give it your build prompt (below). Add your pictures (drag them in, or upload them to the repo on GitHub).
3. **Check:** look at the page Claude made. Ask for changes, one at a time.
4. **Save:** Claude Code commits the files to the repo.
5. **Vercel:** "Add New → Project → Import" your repo → **Deploy**. You get a web address like `sipsquad-site.vercel.app`.
6. From now on, every time Claude Code saves a change to the repo, Vercel updates the site by itself.

**The build prompt** (fill it in from your wireframe and Page Copy doc):
```
Build a one-page website for my brand "[name]" as plain HTML, CSS and JavaScript (an index.html file, a style.css file and an images folder).
Sections in this order: [hero, reasons, how it works, proof, call to action, footer], using the exact words from my copy below.
Brand: colors [codes], fonts [names], my logo is images/logo.png.
Put my launch video in "How it works" from this YouTube link: [link].
Rules: phone first, big buttons, alt text on every picture, easy-to-read contrast.
Explain what you made in simple words.
[paste your Page Copy]
```

## 3. Hands-on build — Build and go live (45 min · 1-on-1: 31 min)
1. Make the GitHub repo. Open Claude Code and connect it.
2. Add your pictures and paste your build prompt.
3. Check every section against your wireframe. Ask for fixes: "Make the hero button bigger." "Use our teal #1CB0F6 for buttons."
4. Check the phone view (ask Claude Code how to preview it, or open it on your phone after deploying).
5. Import the repo in Vercel and deploy. Open your live link on a phone.

**Checkpoint 1 (+20 XP):** the page has all 6 sections with your words, colors and logo.
**Checkpoint 2 (+20 XP):** the site is live on Vercel, video included, and opens on a phone.

Buttons can point to "#" for now. Next lessons add the store and the order form.

```group
Walk around and ask: "Which part of your wireframe is this?"
```

```solo
Let the student drive. You hold the wireframe and copy and read out the next section. When Claude Code asks a question, the student answers it, not you. Celebrate the first live link!
```

> 🛡️ **Sharing moment:** your site is public. Use your brand email, never your personal phone or home address. Keep your GitHub repo free of passwords and secret keys.

## 4. Game / challenge — Plan vs. Page (10 min · 1-on-1: 7 min)
Hold the wireframe next to the live page. Find everything that got lost or changed. 1 point per thing you find, 1 more for fixing it.

```group
Pairs check each other's site. Most fixes: +15 XP. Everyone: +5.
```

```solo
**Student vs. Bolt.** You check their site; they check a demo site you made with 4 hidden mistakes (a missing button, a broken video, a wrong color, a typo). +15 XP for playing, +5 for finding all 4.
```

## 5. Share-out — Launch link (10 min · 1-on-1: 5 min)
Open the live site on a phone. Feedback: *I like… / I wonder… / Try…*

```solo
The student sends you the link, and you open it on your phone while they watch. Say your first thought out loud.
```

## 6. Exit ticket (5 min)
1. What do GitHub, Claude Code and Vercel each do?
2. How did you put your video on the page?
3. What's one thing you'll improve next lesson?

```solo
Ask out loud. Add #3 to their fix list.
```

## Differentiation
- **Extra help:** ask Claude to make the page as an artifact first (like lesson 1) and publish that link. Move to Claude Code + Vercel in the next lesson.
- **Extra challenge:** add a second page ("About us" or "FAQ") and a menu. Make the FAQ with Claude, then check every answer is true.
- **1-on-1 tip:** take a phone photo of the wireframe and keep it open next to Claude Code. Ticking off boxes feels great.
