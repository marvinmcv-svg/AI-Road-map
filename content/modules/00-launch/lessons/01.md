## Lesson objectives
Students will be able to…
- Define **AI**, **model**, **training data** and **prediction** in their own words.
- Train a simple image model and explain why it gets some predictions wrong.
- Explain how the quality and variety of training data affects AI.

## Vocabulary today
AI · model · training data · prediction · pattern · bias (preview)

---

## 1. Warm-up — "Can a computer read your doodle?" (10 min)
1. Students open **Quick, Draw!** in pairs and play 2 rounds (6 doodles each).
2. On mini-whiteboards, each pair answers: *"How do you think it guessed? Where did it learn?"*
3. Collect 3–4 guesses on the board — don't correct yet.

```teacher
Welcome to the AI Creators Guild! This year you won't just USE AI — you'll understand it and build real things with it. First question: how did that game know your squiggle was a cat?
```

## 2. Mini-lesson — Input → Pattern → Prediction (15 min)
Show **Visual 1** and walk through it with the Quick, Draw! example:
- **Training data:** millions of doodles that people already labelled ("cat", "bike").
- **Model:** the computer found patterns — cats have pointy ears and whiskers.
- **Prediction:** your new doodle is compared to those patterns → "I'm 87% sure it's a cat."

Key line to repeat: **"AI doesn't know. It predicts from patterns."**

Worked example (think aloud): "If all the training doodles of 'apple' were red circles with a stem, what happens if I draw a green apple with no stem?" → it might guess "circle" or "ball". The data shapes the AI.

Quick check (thumbs up/down): "AI understands things like a person does." (👎) "Better data → better predictions." (👍)

## 3. Hands-on build — Train your own model (35 min)
Pairs open **Teachable Machine → Image Project → Standard**.
1. **Class 1:** "Pencil" — hold up a pencil and record ~50 webcam samples from different angles.
2. **Class 2:** "Eraser" — same.
3. **Class 3:** "Nothing" — empty background.
4. Click **Train Model**, then test in the Preview panel.
5. Fill in the **Training Data Detective** worksheet:

| Test | What I showed | What the AI predicted | % confidence | Right? Why/why not? |
|---|---|---|---|---|
| 1 | Pencil, normal | | | |
| 2 | Pencil, upside down | | | |
| 3 | A pen (never trained) | | | |
| 4 | Pencil in dim light | | | |

**Checkpoint 1 (+20 XP):** model trained and 4 tests recorded.
**Checkpoint 2 (+20 XP):** pair writes one sentence: "Our model was wrong when ___ because the training data ___."

> 🛡️ **Safety moment:** We point the webcam at OBJECTS, not faces. Pictures of people are personal data — we never collect classmates' faces without permission.

## 4. Game / challenge — "Break the Model" (15 min)
Houses compete: each pair gets 5 minutes to make their model **confidently wrong** (90%+ on the wrong answer). Then they must explain the trick in one sentence using the word *training data*.
- 15 house XP for each pair with a valid explanation; +15 for the most creative break.
- Typical breaks: new object similar in shape, different background, lighting changes, half-hidden object.

## 5. Share-out — "Mini TED talk" (10 min)
3 pairs present their best break (60 seconds each): What did you show? What did the AI predict? Why? Class connects it back to the diagram. Teacher introduces the word **bias**: "Our model only saw pencils on a white table — that's a biased dataset."

## 6. Exit ticket (5 min)
1. In your own words, what is **training data**?
2. Why did your model make a mistake? (Use the word *pattern*.)
3. One question you have about AI.

## Differentiation
- **Support:** pre-made worksheet with the first row filled in; partner reads steps aloud; "pattern" sentence frame provided.
- **Extension:** add a 4th class and test whether more classes make the model less confident; try an Audio Project (claps vs. snaps).
