## Lesson objectives
By the end, the student can…
- Explain **human in the loop** and why AI drafts need checking.
- Add an approval step so only approved replies get sent.
- Decide which jobs can run alone and which need a check.

## Words for today
- **Human in the loop** — a person checks the AI's work before it counts.
- **Approve** — say "yes, this is OK to send".
- **Risk** — how bad it would be if something went wrong.
- **Spot-check** — checking some of the work, not all of it.
- **Audit trail** — a record of who approved what, and when.

## 1. Warm-up — Would you send it? (10 min · 1-on-1: 5 min)
```teacher
AI can write fast, but it can be wrong. Today you add a human check before anything gets sent. Would you send these drafts?
```

Show 3 AI drafts with a hidden problem: a promise you can't keep ("We'll refund you double!"), a wrong price, a rude tone. Would you send them? What would happen if you did?

```solo
The student finds all 3 problems. Then ask: "If a robot sent 100 replies a day with no check, how many would be like this?"
```

## 2. Mini-lesson — Where do checks go? (12 min · 1-on-1: 8 min)
Show **Visual 1**, the **Risk Grid**:
| | Happens rarely | Happens a lot |
|---|---|---|
| **Low risk** (a thank-you note) | Robot does it | Robot does it, spot-check weekly |
| **High risk** (money, angry customer, private info) | Human does it | Robot drafts, **human approves every one** |

**The approval loop** (**Visual 2**): AI drafts → human reads → ✅ approve, ✏️ edit, or ❌ reject → only ✅ rows are sent → the sheet records "Sent" and the time.

**Good checker habits:** read the whole draft, check facts against Store Facts, check the tone, never approve in bulk without reading.

## 3. Hands-on build — Add the approval step (43 min · 1-on-1: 30 min)
1. Add columns: **Approve?** (checkbox), **Sent** (date and time).
2. Ask Claude to update your script:
```
Update my Apps Script: add a menu item "Helper → Send approved replies". For each row where "Approve?" is checked and "Sent" is empty, email the "Draft reply" to a test address [your test email], then write the date and time in "Sent". Never send rows that aren't checked. Explain each part simply.
```
3. Review all 20 drafts. Approve, edit, or leave unchecked.
4. Run **Send approved replies**. Check that ONLY approved rows were sent (to your test address).
5. Fill in your Risk Grid for 5 store jobs.

**Checkpoint 1 (+20 XP):** approval column and send menu work; unchecked rows are never sent.
**Checkpoint 2 (+20 XP):** 20 drafts reviewed + Risk Grid for 5 jobs.

```group
Pairs review each other's drafts as a second checker.
```

```solo
You approve a few rows "by accident" without reading. Can the student catch the bad one before it's sent? Talk about what makes a good checker.
```

> 🛡️ **Test address moment:** while practicing, every email goes to a test address you own, never to a real person.

## 4. Game / challenge — Speed Checker (10 min · 1-on-1: 7 min)
10 drafts, 3 minutes. Approve the good ones, fix or reject the bad ones. Points for each right call; lose points for approving a bad one.

```group
Highest score: +15 XP. Everyone: +5.
```

```solo
**Student vs. Bolt.** Same 10 drafts, both check them on paper. Compare. Approving a bad one costs 2 points! +15 XP for playing, +5 for the win.
```

## 5. Share-out — The full loop (10 min · 1-on-1: 5 min)
Run it live: sort → draft → approve 3 → send → see "Sent" times.

```solo
The student runs the full loop while explaining each step out loud.
```

## 6. Exit ticket (5 min)
1. What does "human in the loop" mean?
2. Name a store job that needs a check on every reply. Why?
3. What's one good checker habit?

```solo
Ask out loud. Save the Risk Grid in their portfolio.
```

## Differentiation
- **Extra help:** approve by typing "yes" in a column instead of a checkbox. Use the exact prompt.
- **Extra challenge:** add an "Edited?" column and count how often humans had to change the AI's draft. That's a great quality score.
- **1-on-1 tip:** talk about real-world checks the student already knows: a teacher grading, a manager signing off. Same idea.
