## Lesson objectives
By the end, the student can…
- Design an AI feature that helps their user (with clear instructions and limits).
- Explain why the API key must live on a **server**, never in the app.
- Build it with a Vercel function, a login check and a daily limit, and check the cost.

## Words for today
- **Server function** — a small piece of code that runs on Vercel's computers, not on the phone. It can keep secrets.
- **Environment variable** — a secret setting stored on Vercel (like `ANTHROPIC_API_KEY`), not in the code.
- **System prompt** — the instructions your app gives Claude every time (like a Claude Project's instructions).
- **Rate limit** — a cap on how many AI requests each user can make (like 20 a day).
- **Cost per use** — how much one AI request costs you.

## 1. Warm-up — What would AI add? (10 min · 1-on-1: 5 min)
```teacher
Today you put Claude inside your app! It can coach, quiz or sum things up. We will keep the key secret and set a daily limit. Where would AI help?
```

Look at your app. Where would a smart helper make it better? Ideas: a tutor that quizzes you on your notes, a coach that looks at your week, a one-line summary of your diary, smart suggestions for your budget.

```solo
You both list 3 AI ideas for the student's app, then pick the one that helps the user most.
```

## 2. Mini-lesson — Where the key lives (15 min · 1-on-1: 10 min)
Show **Visual 1**: **app (phone) → your Vercel function (has the key) → Claude API → answer back to the app.**

**Why not call Claude straight from the app?** Anything in the app can be seen by anyone who opens it. Your key would be stolen and your credits spent. The **server function** keeps the key hidden.

**Safety rules for the AI feature:**
1. Key only in **Vercel environment variables** (`ANTHROPIC_API_KEY`).
2. The function only answers **logged-in** users (check the Supabase login).
3. A **daily limit** per user (like 20 requests), and a **max length** for what they send.
4. A **system prompt** with clear rules: what the helper does, what it never does, when to say "I'm not sure".
5. A low **monthly spending limit** in the Claude Console.

**Picking a model:** Claude Opus 5.5 (`claude-opus-5-5`) gives the best answers; Claude Haiku 5.5 (`claude-haiku-5-5`) is faster and much cheaper. Try both and check the cost in Console → Usage.

## 3. Hands-on build — Claude inside (40 min · 1-on-1: 28 min)
1. Write the AI feature's **system prompt** (role, job, rules, tone, when to say "I'm not sure").
2. Add `ANTHROPIC_API_KEY` in Vercel → Settings → Environment Variables.
3. Ask Claude Code:
```
Add an AI feature to my app: [describe it]. Use a Vercel server function that calls the Claude API (Messages API) with model claude-opus-5-5.
Read the API key from the ANTHROPIC_API_KEY environment variable. Never put the key in the app code.
Only answer logged-in users (check the Supabase login token). Limit each user to 20 requests a day and 1,000 characters per message, and show a friendly message when they hit the limit.
Use this system prompt: [paste]. Show a loading message while waiting and a friendly error if something fails.
Explain each part simply.
```
4. Deploy and test with your 5 test questions. Check the answers and the cost.

**Checkpoint 1 (+20 XP):** the AI feature works on your phone, key only in Vercel settings.
**Checkpoint 2 (+20 XP):** login check + daily limit work, and you wrote down the cost of 10 requests.

```group
Pairs search each other's repos for "sk-ant" (the start of a Claude API key). It must not be there!
```

```solo
Before the first deploy, search the repo together for the key. Then be a tricky user: try to get the helper to do something it shouldn't. The student fixes the system prompt.
```

> 🛡️ **AI safety moment:** your app's AI talks to real people. If it's a diary or wellness app, it must never act like a doctor or therapist. Tell it to gently suggest talking to a trusted person or a professional when someone seems in trouble.

## 4. Game / challenge — Trick the Tutor (10 min · 1-on-1: 7 min)
Try to make the AI feature break its rules: ask it to ignore its instructions, ask something off-topic, send a giant message, send 25 requests. Does it hold?

```group
Every app that holds against 4 tricks: +15 XP. Everyone: +5.
```

```solo
**Student vs. Bolt.** You try 4 tricks on their AI feature; they try 4 on your demo. Each trick that's blocked = 1 point for the builder. +15 XP for playing, +5 for the win.
```

## 5. Share-out — Smart app demo (10 min · 1-on-1: 5 min)
Show the AI feature helping with a real example. Say what 10 requests cost.

```solo
The student demos it and explains where the key lives, in their own words.
```

## 6. Exit ticket (5 min)
1. Why must the API key live in a server function, not in the app?
2. Name 3 limits you added to keep the feature safe and cheap.
3. What should your AI do if a user seems to be in trouble?

```solo
Ask out loud. Check the Console usage together before you finish.
```

## Differentiation
- **Extra help:** a single "Summarize my week" button (no chat). Use the exact prompt.
- **Extra challenge:** stream the answer word by word, or let the tutor use the user's own saved notes as its facts.
- **1-on-1 tip:** look at the cost together after testing. Seeing real numbers makes "limits" feel important, not boring.
