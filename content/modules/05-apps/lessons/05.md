## Lesson objectives
By the end, the student can…
- Plan the **data model** for their app as a simple table.
- Explain the 4 data actions: **add, show, edit, delete** (CRUD).
- Make their app save data on the phone, so it's still there after closing.

## Words for today
- **Data** — the info your app keeps (glasses of water, diary entries, expenses).
- **Data model** — a plan of what you save, like the columns of a table.
- **Field** — one piece of info about an item (date, amount, note).
- **CRUD** — Create (add), Read (show), Update (edit), Delete. The 4 things apps do with data.
- **Local storage** — saving data on this phone or computer only.

## 1. Warm-up — The forgetful app (10 min · 1-on-1: 5 min)
```teacher
An app that forgets is no fun. Today your app learns to remember. Let's test it. Add something, close the app and open it again.
```

Open your version 1. Add something. Close the app completely. Open it again. Is it still there? (Probably not!) Why does that matter?

```solo
Try it together on the student's phone. Then try it on your demo app (which remembers). What's different?
```

## 2. Mini-lesson — Data as a table (12 min · 1-on-1: 8 min)
Show **Visual 1**. Every app's data is like a table:

| Item | Fields | Example |
|---|---|---|
| Water log | date (date), glasses (number), note (text) | Nov 20, 6, "long lab day" |
| Expense | date, amount (number), category (text), paid with card (yes/no) | Nov 20, $8.50, food, yes |

**The 4 actions (CRUD):** add a new row · show the rows · edit a row · delete a row. Most app screens are just these 4 actions!

**Local storage:** the app saves the table on THIS phone. Fast, private and simple. But it doesn't sync to other devices, and it's gone if you clear the browser. (Lesson 7 adds cloud saving and login.)

## 3. Hands-on build — Make it remember (43 min · 1-on-1: 30 min)
1. Fill in the Data Table sheet for your app: items, fields, types, examples.
2. Ask Claude (chat) to check it: "Here's my app idea and data model: [paste]. Is anything missing for my user stories? Is anything not needed?" Remove what you don't need.
3. Ask Claude Code:
```
Make my app save real data on the device (local storage) using this data model: [paste].
Make add, show, edit and delete work on these screens: [list]. Remove the fake sample data.
Show a friendly message when there's no data yet. Keep everything else the same.
Explain how the saving works in simple words.
```
4. Test: add 3 items, edit one, delete one, close the app fully, reopen. Still right?
5. Deploy, and test again on your phone from the home screen.

**Checkpoint 1 (+20 XP):** data model table done and checked.
**Checkpoint 2 (+20 XP):** add, show, edit and delete all work, and data survives a full close.

```group
Pairs test each other's apps with the close-and-reopen test.
```

```solo
You test the student's app while they watch: add, edit, delete, close, reopen. Every surprise is a bug report they give to Claude Code.
```

> 🛡️ **Privacy moment:** local storage stays on this phone, but anyone who uses the phone can open the app. Don't save passwords or very private info yet.

## 4. Game / challenge — Data Breaker (10 min · 1-on-1: 7 min)
Try to break the saving: type an empty entry, a huge number, emoji, a date in the future, tap Save twice fast. What happens? Fix one problem.

```group
Most bugs found and fixed: +15 XP. Everyone: +5.
```

```solo
**Student vs. Bolt.** You try 5 weird inputs on their app; they try 5 on your demo app. Each bug found and fixed = 1 point. +15 XP for playing, +5 for the win.
```

## 5. Share-out — It remembers! (10 min · 1-on-1: 5 min)
Close and reopen the app live. Show the data is still there.

```solo
Use the app for real until the next lesson. Real data finds real bugs.
```

## 6. Exit ticket (5 min)
1. What does CRUD stand for?
2. Draw your data model as a table with 3 fields.
3. What's one limit of saving on the device only?

```solo
Ask out loud. Ask the student to log real data before next lesson.
```

## Differentiation
- **Extra help:** add and show only today; edit and delete next time. Use the exact prompt.
- **Extra challenge:** add an "Export my data" button that downloads a file, so the user owns their data.
- **1-on-1 tip:** using the app for real between lessons is the best test there is. Ask the student what annoyed them.
